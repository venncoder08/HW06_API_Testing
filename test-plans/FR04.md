# FR04 - Quản lý hồ sơ cá nhân

## 1. Requirement-backed contract

### Endpoints

- `GET /api/users/me` yêu cầu JWT và trả hồ sơ của subject trong token.
- `PUT /api/users/me` yêu cầu JWT và cập nhật `name`, `phone`, `shipping_address` của chính subject đó.

### Rules

- Phone hợp lệ bắt đầu bằng ASCII digit `0`, chỉ chứa ASCII digits và dài 10-11 chữ số.
- Email không được thay đổi.
- User không được cập nhật profile của người khác.
- User không được thay đổi `role`.
- Protected endpoints yêu cầu JWT hợp lệ.
- Response không được lộ password/reset token/secret.

## 2. Default fixture

Mỗi PUT case bắt đầu từ database reset hoặc snapshot độc lập. Trừ khi case ghi rõ khác, body `B0` là:

```json
{
  "name": "Nguyen Van A",
  "phone": "0912345678",
  "shipping_address": "123 Le Loi, Q1, TP.HCM"
}
```

Các case mutation chỉ thay đúng field được mô tả; các field còn lại giữ như `B0`.

## 4. Coverage

- **50 atomic test cases**.
- Domain partitions: JWT, name, phone, shipping address và prohibited fields.
- Boundary: phone 9/10/11/12 chữ số.
- Security: sensitive data, SQLi, XSS API portion, mass assignment, role escalation, ownership.
- Schema: required profile data và forbidden security fields; không tự suy diễn exact response shape.
