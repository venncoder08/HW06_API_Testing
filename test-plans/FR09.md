# FR09 - Áp dụng mã giảm giá

## 1. Requirement-backed contract

### Endpoint

- `POST /api/apply-coupon`.

### Required conditions

- C1: Coupon tồn tại và `is_active = 1`.
- C2: Current time trước `expired_at`.
- C3: `total_amount >= min_order_amount`.
- C4: Có JWT hợp lệ.
- C5: Usage của user trong JWT nhỏ hơn `max_uses_per_user`.

### Formula

```text
percent: discount_amount = total_amount * discount_value / 100
fixed:   discount_amount = discount_value
final_amount = total_amount - discount_amount
```

## 2. Default fixture

Body hợp lệ `B0`:

```json
{
  "code": "SAVE10",
  "total_amount": 500000,
  "user_id": 2
}
```

- `user_id` được thay bằng `userIdA` lấy động sau login.
- Trừ khi case nói khác, JWT là `userTokenA`, usage của user A với coupon đang test bằng 0.
- `INACTIVE10` là fixture database với `is_active=0`.
- Usage count 0, max-1 và max được chuẩn bị bằng fixture/reset. `/api/coupon-usage` chỉ là setup implementation helper, không được tính hoặc assert như API chính thức.
- Mỗi mutation chỉ thay đúng field được nêu; field khác giữ như `B0`.

## 4. Coverage

- **58 atomic test cases**.
- Domain partitions: JWT, code, total amount, user identity.
- Boundary: min-1/min/min+1 cho cả ba coupon seed chính.
- State: usage 0 -> max-1 -> max và isolation giữa hai user.
- Security: JWT, SQLi, identity mismatch/IDOR, quota bypass, sensitive data.
- Formula/schema: chỉ assert các field được specification nêu rõ; không tự định nghĩa exact response shape.
