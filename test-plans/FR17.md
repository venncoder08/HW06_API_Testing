# FR17 - Quản lý mã giảm giá

## 1. Requirement-backed contract

### Endpoints

- `GET /api/coupons`: admin xem coupon.
- `POST /api/admin/coupons`: admin tạo coupon.
- `DELETE /api/admin/coupons/:id`: admin xóa coupon.

### Rules

- Phải có JWT hợp lệ với `role=admin`.
- `code`: bắt buộc, duy nhất.
- `type`: bắt buộc, chỉ `percent` hoặc `fixed`.
- `discount_value`: bắt buộc, dương.
- `expired_at`: bắt buộc, là giá trị ngày có thể parse.
- `min_order_amount`: bắt buộc, `>= 0`.
- `max_uses_per_user`: bắt buộc, `>= 1`.

## 2. Default fixture

Body hợp lệ `C0`:

```json
{
  "code": "HW06_UNIQUE_001",
  "type": "percent",
  "discount_value": 15,
  "min_order_amount": 200000,
  "expired_at": "2099-12-31",
  "max_uses_per_user": 1
}
```

- Mỗi create case dùng code unique riêng, trừ duplicate test.
- Mỗi mutation chỉ thay đúng field được nêu; field còn lại giữ như `C0`.
- Create success được xác nhận bằng GET list, không phụ thuộc exact create response/status ngoài nhóm `2xx`.
- Delete success được xác nhận bằng GET list không còn ID.

## 4. Coverage

- **89 atomic test cases**.
- Domain partitions trên JWT, role, code, type, discount, minimum, expiry, max usage và delete ID.
- Boundary: discount 0/1, minimum -1/0/1, max uses -1/0/1/2.
- State: absent -> created -> listed -> deleted -> absent; duplicate concurrency và double delete.
- Security: admin authorization, SQLi, XSS API portion, mass assignment và unauthorized mutations.
- Schema: chỉ assert required coupon fields và forbidden sensitive data; không tự định nghĩa exact shape/status.
